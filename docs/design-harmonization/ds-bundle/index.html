Accordion A thin wrapper over Radix Accordion. Items are separated by a bottom hairline only — no card, no background. The trigger is text-base font-semibold with a size-4 primary chevron that rotates 180° on open; content animates on the two --animate-accordion-* keyframes. Forms

Field wrappers, the public signup form, and the admin form builder.

Field anatomy Four wrappers — Field, TextareaField, SelectField, CheckboxField — share one useFieldIds hook that generates the id, wires aria-describedby to both the description and the error list, and merges rather than overwrites whatever Conform already put there. Every field is a flex flex-col gap-2 stack in the same order: label, description, control, errors. app/components/forms.tsx

app/components/ui/checkbox.tsx List field (friends) The one repeater in the public form: a guest adds friends up to a configured maximum, each answering the same set of sub-fields. It opens with a full-width hairline instead of a label row, because it is a section break in the form rather than another field. Add and remove are Conform intent buttons, so the whole thing works without JavaScript. app/features/forms/fields/list/view.tsx Signup form The public dinner signup, rendered from a stored field schema: each descriptor picks its own view (text, email, tel, textarea, select, checkbox, list), all of which delegate to the shared field wrappers. Three things are always appended by the route rather than the schema — the privacy checkbox, the form-level error list, and a full-width size="lg" submit. app/routes/dinners_.$dinnerId.tsx
app/features/forms/fields/*/view.tsx
app/features/forms/honeypot-field.tsx Signup form builder The largest composite in the app: the admin editor for a dinner's signup questions. Every question is a collapsible RowCard; three tints classify a row at a glance — plain for an ordinary question, primary for a pinned identity field that cannot be removed, sky for the friends group. It degrades without JavaScript: a <noscript> rule forces every row body open, and reorder/insert/remove are Conform intent buttons. app/components/signup-form-builder.tsx

Navigation

Site chrome: nav bars, tabs, in-page nav, footer, links.

Admin tabs The admin section's only navigation. Underline tabs on a bottom hairline, with a live count pill on the four tabs that have one — the counts are loaded once in the admin layout route, so every child screen shows the same numbers without refetching. Two tabs are admin-only and simply do not render for moderators. app/components/admin-tabs.tsx
app/routes/admin.tsx Footer Like the nav, two separate layouts rather than one that reflows: a desktop row with the lockup opposite two labelled link columns, and a mobile stack where the columns collapse into a single row of links. The column headings are tracked eyebrows at label tone — the same component that heads sections elsewhere. app/components/footer.tsx Links & dividers The small connective tissue: BackLink above a page title, SecondaryCTA beside a primary button, SectionDivider between bands of content, and AutoLink, which turns bare URLs inside user-written copy into anchors. None of these is a Button — they are all deliberately lighter than one. app/components/section.tsx
app/components/auto-link.tsx Section nav In-page navigation for the long admin dinner form. An IntersectionObserver with a -15% 0px -75% 0px root margin — a thin band near the top of the viewport — decides which section is current, so the highlight tracks reading position rather than scroll position. Two shapes: a sticky blurred rail on mobile, a sticky sidebar from md. app/components/section-nav.tsx
app/features/events/components/admin-event-form.tsx Site nav Two entirely separate bars rather than one responsive bar: a 64px desktop row with inline links, and a 56px mobile row whose only control opens a full-screen menu. The item list is built once from auth state (buildNavItems) and shared, so admin and account links appear in both without duplication. app/components/site-nav.tsx

Content blocks

The CMS block views the marketing pages are composed of.

Hero block The landing page's opening block, and the only asymmetric grid in the system: a 46fr / 54fr split giving the image the larger half. Everything in it is optional except the headline — eyebrow, description, actions and meta all render conditionally, so the same block serves a page with a scheduled dinner and one without. app/features/cms/blocks/hero/view.tsx
app/routes/_index.tsx Images & media OptimizedImage is the only way a remote image enters the app: it reserves the box by aspect-ratio, paints a blurred LQIP (or a primary tint when there is none) behind it, and fades the real file in over 300ms — plus a <noscript> copy so the picture still appears without JavaScript. CoverImage wraps it at a fixed 3:2 and supplies a drawn placeholder when an event has no image at all. app/components/optimized-image.tsx
app/components/cover-image.tsx
app/features/cms/blocks/image/view.tsx Text section block Two variants of one block. plain is a two-column band — eyebrow and headline left, body right — on an uneven 1fr / 1.2fr grid. slanted is the same content on a -skew-y-3 primary slab, the single inverted surface in the app and the only place text-primary-foreground appears outside a button. app/features/cms/blocks/text-section/view.tsx

Account & auth

The auth shell, its messaging states and the account page.

Account cards The account page is a stack of one local SectionCard — an optional title and subtitle over a gap-5 body. Each card owns one fetcher form and toasts its own result, so saving a name never disturbs the password card below it. Read-only values reuse the field shell, which is why an unchangeable email still lines up with the inputs above it. app/routes/me.tsx Auth shell A 50/50 split: brand copy on a raised bg-card panel, the form on the page surface. Below md the panel becomes a short banner above the form rather than disappearing, so the page still opens with a voice. The mode prop adds the login/join segmented toggle; screens that are not a choice (reset, invite) omit it. app/components/auth-layout.tsx

app/routes/invite.$token.tsx Google sign-in The one component that deliberately does not use our tokens. Google's brand guidelines fix the surface (#131314), border (#8e918f), text (#e3e3e3) and letter-spacing, so the button hard-codes them — it only borrows our radius, height and focus ring so it still sits in a form. The divider above it is part of the same component. app/features/auth/components/google-button.tsx
app/routes/me.tsx Notices & status screens Three levels of message. AuthNotice is inline in a form — a tinted, bordered block with a leading size-5 icon, in two tones. AuthStatus is the whole screen when there is nothing to do but read — a medallion, a light heading and a body, optionally standalone. RouteErrorContent is the unstyled fallback when a route throws. app/components/auth-notice.tsx
