Try it

  • Type in the signer's Label, or switch its Type. The friend copy follows per keystroke. No debounce is needed because there is no second editable input to remount — the mirror just renders the signer's value.
  • Open the chain. Native popover: open, Esc, click-away and aria-expanded all come from the browser, so the explanation is reachable with JavaScript off.
  • Unlink, inside the popover. The friend key becomes restrictions_2 and the fields become editable in place — no layout jump, because they were always field-shaped.
  • Now flip “this form already has signups” and try again. Unlink is still offered — with a warning about the export.

Why unlink still works after signups

Saving forks a new FormVersion and every submission is pinned to its own, so a renamed key never orphans stored answers. The real cost is that roster columns are a union across versions — the export gains a second column from that point on. For an unlink, that is arguably the honest result.

The one rule

readonly, never disabled, on anything carrying a name — disabled controls are not submitted. Here the visible controls carry no name at all and hidden inputs do the work.

Where it came from

The three directions below were designed in full before E. B contributed the data model and the progressive enhancement; D contributed the layout and the chain. C is kept because its trade-off — scope as a checkbox instead of a naming convention — is the one genuinely different idea, and the reason to revisit it is recorded in the comparison.

    This question appears twice on the signup page — once for the person signing up, and once inside every friend they add. Both copies share the field key restrictions, which is how the roster and the CSV line the answers up into one column, one answer per person. Editing here edits both.

    Try it

    • Untick “Each friend they bring”. The card's chain badge goes, the explainer goes, and the friends block's numbered list loses the question immediately. The preview is derived from the same projection that saves.
    • Untick both. A question nobody answers is caught as a validation error rather than silently vanishing.
    • Retype the Label. One input, two scopes. There is no second copy to fall out of step.

    Drift, handled out loud

    The amber notice on Student is what an existing form looks like when the two copies already disagree. It quotes the friend copy verbatim and offers to keep it — nothing is picked silently.

    The cost

    Card order becomes the order for both scopes. “Ask friends their name last” stops being expressible, and the nested friends list — a free preview of the public form — is replaced by that numbered summary.

    Where it feels different

    Real sync is debounced ~600ms and the peer input remounts, so the value snaps in rather than tracking per-character. This mockup syncs instantly — the shipped version would feel a beat slower.

    With signups

    The keys lock, so unlink is unavailable. The popover says so and offers the real escape hatch — remove the friend copy and add a fresh question with its own key.

    What changed the answer

    “Unlink at any point” looked like the constraint that forced C, because B and D unlink by renaming a field key and the key is the column stored answers live under. Reading the write path settled it: saving forks a new form version and every submission is pinned to its own, so a rename never orphans an answer. The only real cost is that roster columns are a union across versions — the export gains a second column. For an unlink, that is arguably the correct export rather than a bug.

    That freed the choice from the data model and put it back on look and feel, which is how E ends up as D's layout over B's model. It is the only column above with no red in it — at the cost of one deliberate loosening: unlink stays available while field keys are otherwise locked. If that reads as too permissive, gating it is a one-line change and the popover already has the copy for that branch.

    Still open, and recorded rather than decided: per-scope wording. E removes it, and re-adding it later means dropping label from the synced list and restoring the friend-side input — small, but it reopens the drift question E closes. Worth knowing that the roster already merges both scopes into one column, so divergent labels were always partly a fiction in the export.
